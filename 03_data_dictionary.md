# 03_data_dictionary.md — словарь данных PayShield

## 1. Исходный набор `payments.csv`

В исходном `payments.csv` **12 колонок**. Примеры ниже взяты из первой записи исходного файла (`pay_0001`), а не придуманы.

| Поле | Тип | Обязательность | Ограничение | Пример | Проверка/код | Назначение |
|---|---|---|---|---|---|---|
| `payment_id` | string | Да, сервер | `pay_NNNN` или внутренний ID | `pay_0001` | — | Идентификатор платежа |
| `order_id` | string | Да | `^ord_[0-9]{4}$` | `ord_1001` | `INVALID_FORMAT` | Идентификатор заказа клиники |
| `recipient` | string | Да | ID из `recipients.csv`, статус `ACTIVE` | `clinic_medservice` | `RECIPIENT_NOT_FOUND` | Получатель платежа |
| `purpose` | string | Да | 1–200 символов; без PAN/CVV | `Приём терапевта` | `INVALID_PURPOSE` | Назначение платежа |
| `amount` | decimal | Да | > 0; ≤ 1 000 000; не более 2 знаков после точки | `2500.00` | `AMOUNT_OUT_OF_RANGE`, `INVALID_AMOUNT_PRECISION`, `AMOUNT_TYPE_ERROR` | Сумма в рублях |
| `currency` | string | Да | ISO 4217; в проекте только `RUB` | `RUB` | `UNSUPPORTED_CURRENCY` | Валюта платежа |
| `status` | enum | Да, сервер | `CREATED`, `PENDING`, `SUCCESS`, `DECLINED`, `ERROR`, `CANCELED` | `SUCCESS` | — | Текущее состояние |
| `error_code` | string/null | Нет | Код из каталога ошибок | пусто | — | Причина ошибки/отказа |
| `idempotency_key` | string | Да для API/CLI | 8–64 символа; TTL 24 часа | `idem_0001` | `VALIDATION_ERROR`, `INVALID_FORMAT` | Защита от повторной обработки |
| `created_at` | datetime | Да, сервер | ISO 8601 UTC | `2025-11-01T08:00:00Z` | — | Время создания |
| `confirmed_at` | datetime/null | Нет | ISO 8601 UTC; пусто до результата | `2025-11-01T08:00:03Z` | — | Время завершения подтверждения |
| `correlation_id` | string | Да, сервер | Уникальный идентификатор запроса | `corr_0001` | — | Поиск связанных событий в логах |

## 2. Дополнительное поле прототипа `payments_out.csv`

`payments_out.csv` содержит те же 12 бизнес-полей и одно дополнительное техническое поле. При точном повторе CLI возвращает сохранённый результат с `replayed: true`; код `DUPLICATE_REQUEST` обозначает семантику повтора, а не перезаписывает исходный `error_code` платежа:

| Поле | Тип | Обязательность | Ограничение | Назначение |
|---|---|---|---|---|
| `response_json` | JSON string | Да для новых записей; у старых строк может быть пустым | Сериализованный первоначальный ответ | Позволяет вернуть точный ответ при идемпотентном повторе |

Итого: исходный набор `payments.csv` — 12 колонок; журнал прототипа `payments_out.csv` — 13 колонок. Исходный файл не перезаписывается.

## 3. Справочник получателей

`recipients.csv` читается в кодировке Windows-1251 (`cp1251`). Поля: `recipient_id`, `name`, `status`. Для платежа подходят только строки со статусом `ACTIVE`. В загруженном наборе 41 запись, из них 32 активные.

## 4. Состояния платежа

- `CREATED` — платёж создан, ожидает подтверждения (целевой API).
- `PENDING` — шлюз не вернул окончательный результат вовремя.
- `SUCCESS` — эмулятор подтвердил успешную операцию.
- `DECLINED` — эмулятор отклонил операцию.
- `ERROR` — техническая ошибка, не являющаяся штатным отказом.
- `CANCELED` — платёж отменён до подтверждения.

В текущем CLI-прототипе платёж сразу проходит через эмулятор; промежуточный `CREATED` и методы подтверждения токеном не реализованы. Они описаны целевым API и документом `07_confirmation.md`.
