# Требования к платёжному сервису — кейс 1

## Как заполнять

1. В таблице FR оставлена одна заполненная строка (FR-1) — это образец.
Заполни FR-2…FR-10 по той же логике.
2. В таблице NFR оставлена одна строка (NFR-1) — образец. Заполни NFR-2…NFR-6.
3. В колонке «Тест» укажи ID теста из `09\\\_tests.md`, который проверяет
требование. Если требование не тестируется — поставь «—».
4. В разделе «Пользовательские сценарии» опиши 3–5 шагов «как клиент
проходит путь оплаты» от лица пациента.
5. Не выдумывай требований, которых нет в задании или в payments.csv.

## Ограничения (заполните сами, 3–5 пунктов)

* Нет реального платежного шлюза - используется эмулятор.
* Банковские данные не действительны. 
* Сервис не хранит банковские данные после выполнения операции.

## Пользовательские сценарии (заполните, 3–5 сценариев)

### Сценарий 1. Успешная оплата

1. Пациент выбирает услугу и нажимает "Оплатить".
2. Система запрашивает подтверждение (Ввод данных карты).
3. Пациент подтверждает, видит сообщение "Оплата успешна".

### Сценарий 2. Отказ банка

1. Пациент инициирует платеж.
2. Получает уведомление "Платеж отклонен: недостаточно средств.".
3. Может повторить попытку с другой карты.


### Сценарий 3. Неверные данные
1. Пациент инициирует платеж, вводя сумму с тремя знаками после точки.
2. Получает сообщение "Сумма должна иметь не более 2 знаков".
3. Может повторить платеж, введя верную сумму.


### Сценарий 4. Повторная отправка
1. Пациент дважды нажимает оплатить из-за плохого интернета.
2. Система обрабатывает только первый запрос.
3. Пациент видит "Оплачено" без двойного списания.
## Критерий приёмки (что проверяет жюри)

* \[ ] FR-1…FR-10 заполнены, у каждого указан приоритет (Must/Should/Could)
* \[ ] NFR-2…NFR-6 заполнены, они измеримы (секунды, символы, проценты)
* \[ ] Ограничения отражают реальность кейса (нет реального шлюза, синтетические данные)
* \[ ] Сценарии описывают путь пациента, а не внутренности сервиса
* \[ ] В колонке «Тест» стоят ID из `09\\\_tests.md` или «—»

## Подсказки, на что смотреть

* FR — это «что система делает» (глагол + объект): создать, провалидировать, подтвердить.
* NFR — это «как система это делает» (измеримо): за сколько секунд, сколько символов, какой протокол.
* Приоритеты: Must — без этого кейс не сдан, Should — желательно, Could — если успеем.
* В сценариях не нужно писать «сервис вызывает эмулятор». Пиши «пациент нажимает Оплатить → видит результат».
