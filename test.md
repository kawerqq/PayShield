# test.md — пять обязательных тест-сценариев PayShield

**Среда:** Python 3, отдельная временная копия проекта, пустой `payments_out.csv` перед тестами. Тесты не изменяют исходный `payments.csv`.

## T1-1. Успешная оплата

**Вход:** `ord_1001`, `clinic_medservice`, `2500.00 RUB`, `idem_t1_01`.

**Ожидание:** `SUCCESS`, код ошибки отсутствует, одна строка добавлена в `payments_out.csv`.

**Факт:** CLI вернул `SUCCESS`, `error_code: null`; в тестовом `payments_out.csv` добавлена одна запись.

**Пройден:** [x] да [ ] нет

## T1-2. Отказ шлюза

**Вход:** `ord_1002`, `clinic_medservice`, `1500.00 RUB`, `idem_t1_02`. Для этого ID `md5(order_id) mod 10 = 7`.

**Ожидание:** статус платежа `DECLINED`, `error_code = INSUFFICIENT_FUNDS`; запись сохраняется.

**Факт:** CLI вернул `DECLINED` и `INSUFFICIENT_FUNDS`; запись добавлена.

**Пройден:** [x] да [ ] нет

## T1-3. Неверные данные

**Вход:** `ord_1003`, активный получатель, сумма `-10.00`, валюта `RUB`, ключ `idem_t1_03`.

**Ожидание:** `AMOUNT_OUT_OF_RANGE`, HTTP-маппинг 422; шлюз не вызывается и запись платежа не создаётся.

**Факт:** CLI вернул `AMOUNT_OUT_OF_RANGE` и `http_status: 422`; строка в `payments_out.csv` не добавлена.

**Пройден:** [x] да [ ] нет

## T1-4. Повтор запроса (идемпотентность)

**Вход:** два одинаковых запуска с `ord_1004`, суммой `100.00`, ключом `idem_t1_04`.

**Ожидание:** второй ответ повторяет первый, содержит `replayed: true`; в CSV остаётся одна запись.

**Факт:** второй запуск вернул сохранённый ответ с `replayed: true`; число строк после первого и второго запуска одинаковое — 1.

**Пройден:** [x] да [ ] нет

## T1-5. Таймаут эмулятора

**Вход:** `ord_1018`, `clinic_medservice`, `1500.00 RUB`, `idem_t1_05`. Для этого ID `md5(order_id) mod 10 = 9`.

**Ожидание:** статус `PENDING`, `error_code = GATEWAY_TIMEOUT`, exit code 3; событие `TIMEOUT` записано в `gateway.log`. Повтор с тем же ключом безопасен.

**Факт:** CLI вернул `PENDING` и `GATEWAY_TIMEOUT`, exit code 3; в `gateway.log` есть событие `TIMEOUT`. Повтор вернул сохранённый `PENDING`, `replayed: true`, новая запись шлюза не добавлена.

**Пройден:** [x] да [ ] нет

## Примечание о статусах

В CLI поле `http_status` — отображение ожидаемого HTTP-кода для результата (422/402/504 и т. п.), а не фактический HTTP-ответ: HTTP-сервер в проекте не реализован. Валидация — 422, отказ шлюза — 402, таймаут — 504. Успешный финальный ответ CLI помечается 200; целевой `POST /payments` в OpenAPI возвращает 201 на стадии `CREATED`.

## Дополнительные регрессионные проверки

Кроме пяти обязательных сценариев T1-1…T1-5, автоматический набор проверяет:

- конфликт одного `Idempotency-Key` с изменённой суммой (`IDEMPOTENCY_KEY_CONFLICT`);
- повтор пары `order_id + recipient` с новым ключом (`DUPLICATE_ORDER`, HTTP-маппинг 409);
- некорректный тип поля `recipient` (контролируемая ошибка валидации).

Всего в `tests/test_prototype.py` выполняются 8 тестов.
