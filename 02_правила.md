# 02_правила.md — правила валидации и обработки PayShield

**Источник:** задание T1 «Платёжный сервис: безопасный платёж за услугу», исходные `payments.csv` и `recipients.csv`.
**Статус:** правила ниже являются согласованной спецификацией проекта. Реализация CLI отмечена отдельно в `04_requirements.md` и приложении.

| ID | Условие | Действие | Код ошибки | HTTP-контракт |
|---|---|---|---|---:|
| V-1 | Обязательное поле отсутствует или пустое: `order_id`, `recipient`, `purpose`, `amount`, `currency`, `Idempotency-Key` | Отклонить до обращения к шлюзу | `VALIDATION_ERROR` | 422 |
| V-2 | `order_id` не соответствует `^ord_[0-9]{4}$` | Отклонить | `INVALID_FORMAT` | 422 |
| V-3 | `amount` ≤ 0 или > 1 000 000 | Отклонить | `AMOUNT_OUT_OF_RANGE` | 422 |
| V-4 | `currency` не равна `RUB` | Отклонить | `UNSUPPORTED_CURRENCY` | 422 |
| V-5 | `recipient` отсутствует в `recipients.csv` или его статус не `ACTIVE` | Отклонить | `RECIPIENT_NOT_FOUND` | 404 |
| V-6 | `purpose` пустое, длиннее 200 символов, содержит PAN (13–19 цифр подряд) или явно помеченный CVV/CVC | Отклонить | `INVALID_PURPOSE` | 422 |
| V-7 | `amount` содержит более двух знаков после точки либо не соответствует десятичному формату | Отклонить | `INVALID_AMOUNT_PRECISION` / `AMOUNT_TYPE_ERROR` | 422 |
| V-8 | Пара `order_id + recipient` уже есть среди платежей | Не создавать новый платёж; вернуть сведения о существующем с конфликтом | `DUPLICATE_ORDER` | 409 |
| V-9 | Повтор `Idempotency-Key` в течение 24 часов с теми же параметрами | Вернуть сохранённый результат операции с `replayed: true`, не обращаться к шлюзу повторно | `DUPLICATE_REQUEST` (семантика повтора; в JSON CLI используется `replayed: true`, без замены исходного статуса платежа) | 200 |

## Уточнения

1. `Idempotency-Key` передаётся HTTP-клиентом в заголовке. В CLI-прототипе для удобства он передаётся как поле JSON `idempotency_key`.
2. Если ключ повторён с другими параметрами, запрос отклоняется: `IDEMPOTENCY_KEY_CONFLICT`, HTTP 409.
3. Проверка V-9 выполняется раньше V-8: точный повтор запроса должен вернуть первоначальный ответ, а не конфликт дублирующего заказа.
4. Для V-8 используется HTTP 409 согласно подсказке исходных материалов. Существующий платёж включается в ответ, новый не создаётся.
5. `TIMEOUT` — результат эмулятора, не статус платежа. В хранилище платёж получает `PENDING`, код ошибки `GATEWAY_TIMEOUT`.
6. CVV проверяется в назначении только по явной метке `CVV`/`CVC` рядом с 3–4 цифрами. Автоматически отличить произвольные 3–4 цифры от CVV без контекста невозможно.

## Обоснование

- **V-1:** без обязательных данных нельзя однозначно определить заказ, получателя и сумму.
- **V-2:** единый формат идентификатора упрощает проверку и сопоставление заказа.
- **V-3:** диапазон ограничивает некорректные и недопустимые суммы.
- **V-4:** проект поддерживает только рублёвые платежи.
- **V-5:** платёж разрешён только зарегистрированному активному получателю.
- **V-6:** ограничение назначения снижает риск попадания платёжных данных в текстовые поля.
- **V-7:** точность до копейки исключает неоднозначность округления.
- **V-8:** повторная оплата одного заказа не должна создавать вторую запись.
- **V-9:** повторная доставка запроса не должна приводить к повторному обращению к шлюзу или списанию.

## Каталог дополнительных технических ошибок

| Код | Значение | HTTP | Повторять? |
|---|---|---:|---|
| `AMOUNT_TYPE_ERROR` | Сумма не является числом | 422 | Нет |
| `INVALID_REQUEST` | JSON не читается или корень не объект | 400 | Нет |
| `IDEMPOTENCY_KEY_CONFLICT` | Ключ использован с другим содержимым | 409 | Нет |
| `DUPLICATE_ORDER` | Заказ с таким получателем уже существует | 409 | Нет |
| `INSUFFICIENT_FUNDS` | Недостаточно средств (ответ эмулятора) | 402 | Нет |
| `CARD_DECLINED` | Отклонение операции эмулятором | 402 | Нет |
| `GATEWAY_TIMEOUT` | Не получен своевременный ответ шлюза; итог неизвестен | 504 в целевом API; платёж `PENDING` | Только безопасная проверка статуса |
