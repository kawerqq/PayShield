# 08_gateway_emulator.md — эмулятор платёжного шлюза

## 1. Назначение и границы

Эмулятор заменяет внешний эквайринг в учебном кейсе. Он принимает `order_id`, `amount`, `currency` и возвращает детерминированный результат. Реального банковского списания нет.

В текущем CLI `emulate_gateway(order_id)` — локальная функция Python. HTTP-маршрут `POST /gateway/charge` в коде не поднят; такой маршрут является логической схемой взаимодействия, а не работающим сетевым endpoint.

## 2. Детерминированные сценарии

Алгоритм: `bucket = int(md5(order_id).hexdigest(), 16) % 10`.

| bucket | Результат эмулятора | Статус платежа PayShield | `error_code` |
|---:|---|---|---|
| 0–6 | `SUCCESS` | `SUCCESS` | — |
| 7 | `DECLINED` | `DECLINED` | `INSUFFICIENT_FUNDS` |
| 8 | `DECLINED` | `DECLINED` | `CARD_DECLINED` |
| 9 | `TIMEOUT` | `PENDING` | `GATEWAY_TIMEOUT` |

Для одинакового `order_id` результат всегда одинаков. MD5 здесь используется только для воспроизводимого выбора учебного сценария, не для защиты данных или подписи.

## 3. Контрольные идентификаторы для тестов

| `order_id` | bucket | Ожидаемый сценарий |
|---|---:|---|
| `ord_1001` | 1 | SUCCESS |
| `ord_1002` | 7 | INSUFFICIENT_FUNDS |
| `ord_1007` | 8 | CARD_DECLINED |
| `ord_1018` | 9 | TIMEOUT |

## 4. Формат логирования `gateway.log`

Каждое обращение эмулятора добавляет одну JSON-строку:

| Поле | Назначение |
|---|---|
| `timestamp` | Время события в UTC |
| `order_id` | Идентификатор заказа |
| `correlation_id` | Связь с записью основного журнала |
| `result` | `SUCCESS`, `DECLINED` или `TIMEOUT` |
| `error_code` | Код отказа/таймаута или `null` |
| `duration_ms` | Длительность; в синхронном локальном эмуляторе сейчас `0` |

В `payment_service.log` фиксируются ошибки валидации, конфликты, повторы и итог обработки. PAN, CVV, токены подтверждения и секреты в журналы не записываются.

## 5. Примеры логического обмена

Запрос, который целевой HTTP-эмулятор мог бы принимать:

```json
{
  "order_id": "ord_1001",
  "amount": 2500.00,
  "currency": "RUB"
}
```

Успешный ответ:

```json
{
  "status": "SUCCESS",
  "error_code": null
}
```

Отказ:

```json
{
  "status": "DECLINED",
  "error_code": "INSUFFICIENT_FUNDS"
}
```

Таймаут — отсутствие своевременного ответа; PayShield сохраняет `PENDING` и `GATEWAY_TIMEOUT`. Это не означает, что платёж точно не прошёл.

## 6. Проверка

Повторный запуск одного `order_id` на уровне чистой функции `emulate_gateway` должен возвращать одинаковую пару `(status, error_code)`. Повторный запрос клиента с тем же `Idempotency-Key` обрабатывается раньше вызова эмулятора и не создаёт вторую запись.
